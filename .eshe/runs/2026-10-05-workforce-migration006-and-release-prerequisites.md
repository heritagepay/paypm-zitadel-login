| Migration | Owned tables / preservation |
| --- | --- |
| 001 | `login_workforce_epochs`, challenges, attempts, admissions, revocations, passkey attempts. Binding/retirement triggers protect recorded ceremonies; current SQL admission and revocation are authoritative before provider cleanup. |
| 002 | `login_legacy_recovery_retirements`, historical immutable retirement provenance. |
| 003 | `login_workforce_action_intents`, fixed action/session/context and bounded transitions. |
| 004 | `login_operations_action_requests`, original operation/caller/provider proof custody and bounded state transitions. |
| 005 | `login_operations_logouts`, immutable retirement provenance with allowed terminal material erasure. |
| 006 | `login_identity_logouts`, exact request-hash, original admission, provider IDs and revocation time. Current code only SELECTs/INSERTs this journal; SQL file itself has no immutable UPDATE/DELETE/TRUNCATE trigger. Runtime grants must preserve insert/read-only journal behavior. This slice does not change the schema. |

No Login migration contains CREATE ROLE or GRANT, and no audited operator/chart source supplies a Login database topology. Existing database-owner credentials are not a suitable runtime shortcut.
