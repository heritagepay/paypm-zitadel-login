# Governed original commercial credential retirement

Existing ZITADEL Login owns the provider effect; Identity owns the independently approved canonical recovery case; Access owns the bounded native continuation, target-contact proof and minimum twenty-four-hour money-release hold. No OTP, email/phone match, case ID or arbitrary actor header authorizes retirement. No live mutation is implied by source qualification.

## Exact private contracts

`POST /api/internal/v1/recovery/legacy-retirements` requires a distinct `PAYPM_LEGACY_RECOVERY_CALLER_TOKEN` and strict `{caseId,decisionId}`. Login derives original issuer/subject, canonical Person, target, app/deployment/environment, maker/reviewer and immutable proof from `POST /internal/v1/recovery-cases/:id/legacy-revocation-context {decisionId}`. The Identity reader uses the dedicated `IDENTITY_LEGACY_RECOVERY_REVOKER_SERVICE_SUBJECT`, sole `identity.directory.read` capability and its explicit purpose route fence; it cannot list people, write contacts, bind subjects or use other directory routes. Current canonical active Person, historical workforce classification, current independent reviewer eligibility/capability and exact consumed review proof are checked by Identity.

The response is exactly `{revocationEvidenceId,caseId,decisionId,personId,originalAuthentication:{issuer,subject},appId,deploymentId,environment,kind:'legacy_profile_retired',oldSessionsRevokedAt}`. The evidence ID is the durable retirement operation. The time is the current confirmed inactive-profile/canonical-case observation, not a claim about token-byte deletion. Access compares the complete case binding and persists the observation before target activation. Retrying the same private POST reads current provider state and original immutable operation.

## Provider behavior

The pinned ZITADEL v4.15.3 [DeactivateUser API](https://github.com/zitadel/zitadel/blob/v4.15.3/proto/zitadel/user/v2/user_service.proto) permanently retires the old commercial profile in this workflow. The [access-token reader](https://github.com/zitadel/zitadel/blob/v4.15.3/internal/query/access_token.go) rejects prior tokens after user deactivation events; [refresh exchange](https://github.com/zitadel/zitadel/blob/v4.15.3/internal/command/oidc_session.go) checks current user enabled state before issuing replacements; the [session projection](https://github.com/zitadel/zitadel/blob/v4.15.3/internal/query/projection/session.go) removes the deactivated user's Session API rows. These are current-authority effects, not deletion of refresh-token storage. Consumers that verify only an old JWT signature remain unsafe; protected APIs must perform current authority validation.

Login verifies the exact provider human profile and its registered commercial organization, durably reserves the immutable case/decision/binding before calling the provider, then requires actual `USER_STATE_INACTIVE` readback and a second current canonical case read. Unknown write outcomes are resolved by provider state, never a caller Boolean. Concurrent claims are serialized, and an active-profile retry must first read current state; attempts are bounded and cannot blindly repeat within ten seconds. A retired operation observing an active old profile denies. Recovery rollback must never reactivate the old profile; retained Identity links and financial IDs remain historical evidence.

## Configuration and qualification gates

Missing configuration denies. `PAYPM_LEGACY_RECOVERY_ISSUER` is a server-owned exact origin. `PAYPM_LEGACY_RECOVERY_CONTEXTS_JSON` contains exact `{appId,deploymentId,environment,organizationIds}` entries. Every organization is explicitly commercial; `PAYPM_WORKFORCE_ORGANIZATION_ID` and `PAYPM_LEGACY_RECOVERY_SERVICE_ORGANIZATION_ID` are required exclusions. Machine profiles and any Identity workforce classification for the exact original issuer/subject deny.

Separate `PAYPM_LEGACY_RECOVERY_IDENTITY_URL/TOKEN_URL/CLIENT_ID/CLIENT_SECRET/SCOPES` and `PAYPM_LEGACY_RECOVERY_PROVIDER_TOKEN_URL/CLIENT_ID/CLIENT_SECRET/SCOPES` configure the read-only canonical case reader and native provider actor. Provider permissions must be limited to reading/retiring users in the qualified commercial organizations. They must not be the workforce Login actor, arbitrary user administration, a human OTP credential or a broad instance administrator. The caller purpose token must differ from provider/Identity secrets, store key and workforce admission token. HTTPS origins, private routes, no redirects and bounded timeouts are enforced.

Apply forward Login migrations with `bun scripts/migrate-workforce.mjs` under the dedicated migration database role. Migration002 preserves immutable retirement evidence and supports identical readback. Real PostgreSQL tests qualify concurrent immutable reservation/confirmation; synthetic provider tests qualify case mismatch, workforce/service/machine exclusion, missing policy, restored profile denial and lost-response readback. Real provider permissions, exact registered organizations, deployed image, current introspection/refresh denial and authorized independent reviewer/native actor behavior remain release gates.
