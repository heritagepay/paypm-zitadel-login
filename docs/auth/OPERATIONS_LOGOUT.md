# Operations app logout and delayed retirement

Login current admission remains authoritative for all protected Operations requests. Browser cookie removal or an end-session redirect alone is insufficient. The Operations BFF reserves an encrypted immutable logout outbox before clearing browser state, retaining the exact original accepted proof pair, canonical audit and retirement-only capture. Local session/callback epochs deny immediately; no refresh or session restoration happens during logout.

## Retirement-only capture

Successful current POST `/api/internal/v1/operations/admissions/check` keeps its exact22-field JSON and adds response header `X-PayPM-Operations-Retirement-Proof`. Format is `/^paypm-oplogout1\.[A-Za-z0-9_-]+\.[A-Za-z0-9_-]{43}$/`, maximum16384characters. This private HMAC-SHA256 capture is signed using separate canonical32-byte `PAYPM_OPERATIONS_RETIREMENT_PROOF_KEY_BASE64`; it must differ from Login encryption, flow, action, reader, introspection and logout purposes. Keep its custody/rotation history until all outstanding bounded outboxes have retired; removing the signing key makes those tickets unavailable.

The signed payload has version1, purpose `operations_session_retirement`, issuance/expiry and the actual complete22-field admission, including canonical Person, exact issuer/provider subject/genuine base Session API ID/client/app/deployment/environment/context, original OIDC request/challenge/epoch and SHA256 of original ID token/access token/nonce. Expiry is original admission absolute expiry plus seven days. This ticket cannot authenticate, refresh, grant permissions or prove action freshness. Its only effect is retirement of that historically admitted exact base and dependent provider sessions. The current provider signed proof pair is still mandatory for ordinary admission; an expired pair is never accepted as authentication.

The BFF atomically retains the newest ticket with each accepted initial/refreshed pair and frozen admission, then freezes that exact capture in the durable logout outbox. An unavailable owner until the access token expires does not require a guessed JWT session or subject-only grant: first retirement verifies the ticket and all raw proof hashes against retained immutable Login admission. Original global epoch may have moved or admission may already be inactive; this cannot produce new authority. OTP readiness switching off does not prevent retiring an already issued valid ticket.

## Exact private producer contract

POST `/api/internal/v1/operations/sessions/logout`, Bearer distinct `PAYPM_OPERATIONS_LOGOUT_TOKEN` (minimum32characters, never reuse any reader/action/key purpose). Strict body exactly `{requestId,operationKey,idToken,accessToken,nonce,clientId,retirementProof}`, caller-generated request/operation UUIDv4, maximum32KiB. No issuer, actor, Person, subject or arbitrary session input is accepted. Same operation/request preserves the entire original body; changing a pair or ticket conflicts. No raw tokens/ticket enter audit logs or response.

Login transaction locks the originally admitted base, verifies historical exact issuer/subject/client/OIDCrequest/challenge/epoch from signed capture, queues that base and actual dependent Identity/Operations ceremony provider IDs, revokes its admission, retires dependent requests and clears encrypted provider/caller/assertion/receipt material. Other workforce sessions and global user epoch are unchanged. The canonical Person and original operation/request remain immutable SQL audit. Provider effect occurs only after local revocation; late action verification and callbacks cannot restore admission.

Success has exactly15fields: `{requestId,operationKey,personId,issuer,providerSubject,baseSessionId,clientId,appId,deploymentId,environment,contextId,state:'revoked',revokedAt,providerRetirement:'confirmed'|'pending',checkedAt}`. `state:'revoked'` means durable Login admission denial. Pending provider retirement is truthful and must be retained by the BFF outbox. POST `/api/internal/v1/operations/sessions/logout/readback` uses identical original body and purpose credential after an uncertain accepted effect. If no exact retained logout exists and the original capture/signature/hash tuple is valid, readback returns HTTP404 exactly `{code:'operations_logout_not_found'}`. Invalid/expired never-accepted capture or a conflict denies403. Only that explicit valid not-found permits retrying the initial endpoint with the same immutable operation/body. Uncertain/malformed/unavailable responses retain the sealed original outbox and never generate a new UUID or restore a session.

Provider retirement first reads the actual exact Session API ID and checks subject/OPS organization, then deletes and rereads classified NotFound. Empty/malformed/failed readback is not confirmation. An uncertain result stays queued; identical retry rereads before any deletion. Actual already-absent session is confirmed idempotently. The private Operations cleanup/retirement worker must run≤60seconds and retain uncertain outcomes. No live provider deletion has been performed by this slice.

Migration005 adds immutable logout audit and forward-only terminal secret-erasure guard for existing Identity action material. It does not rewrite migration003, restore an old proof, change financial IDs or grant product permissions. Missing config/database/capture, wrong proof/hash/client/namespace/historical binding or unaccepted readback denies.

## Public PKCE refresh-token revocation

The actual Operations client is public PKCE. It has no client secret. Pinned ZITADEL4.15.3 uses zitadel/oidc/v3v3.47.5; `ParseTokenRevocationRequest` requires form `client_id` when no Basic auth is supplied, checks native `AuthMethodNone` when `client_secret` is empty and permits the public client. The BFF therefore posts only `{client_id:<registered configured Operations client>,token:<its actual retained refresh token>,token_type_hint:'refresh_token'}` as form data to fixed issuer `/oauth/v2/revoke`; no invented confidential credentials or PKCE verifier. The pinned command checks actual OIDC session client ownership. Unknown/already-revoked token may still return200, so that response alone is not proof of Login admission revocation or a financial authorization. Retained JWT signature may still be valid; current admission is denied regardless of browser navigation or refresh issuer behavior.
