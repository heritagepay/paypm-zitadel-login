# Operations action reauthentication

Operations owns its current capabilities, resource relationships, immutable maker/checker commands and financial state. Login owns the fresh ZITADEL ceremony and short-lived single-use proof. The Identity staff namespace and its receipts are separate. No OPS organization membership, local flag, actor header or limited email session grants an Operations action.

The initial catalogue is `operations.merchant.settlement.review`, `.approve`, `.execute`. All phases retain the owning `command.operationKey`; the active ceremony index includes canonical Person and action so independent phases do not collide. The backend owns grant/resource checks before and after proof. The exact frozen owner fixture is `apps/login/test-fixtures/operations-action-authority.json`, independently copied from backend checkpoint b1d6439 and qualified by canonical hash and HMAC tests. It contains only synthetic identifiers and a fixture-only key.

## Private BFF contract

All routes are private, HTTPS, no-store, strict JSON, bounded input and purpose credentials. No private receipt is placed in a URL or returned to browser JavaScript.

- `POST /api/internal/v1/operations/actions/requests`, Bearer `PAYPM_OPERATIONS_ACTION_BFF_TOKEN`: `{requestId,idToken,accessToken,nonce,clientId,callbackState,action,payloadHash,command}`. Caller generates request UUIDv4 and retains original owning operation UUID; state is 64 base64url characters. Server verifies the original raw proof pair through current Login admission, derives Person/session/client/context/deployment/environment, and reads the owning authority. Response `{requestId,expiresAt,redirectUrl}` opens the Login origin ceremony with a bounded opaque capability.
- `POST /api/internal/v1/operations/actions/requests/:requestId/readback`, same BFF purpose: `{expected,command}`. A verified terminal result is `{requestId,state:'verified',receipt,expiresAt,expected,command,capabilityDecisionId}`. A cancelled terminal result contains the same fields except receipt/expiry and state is `cancelled`. The caller's state, original request and session epoch must match its durable BFF reservation. An unknown request is not a grant.
- Fixed registered callback is `https://<registered Operations origin>/auth/workforce/actions/callback?requestId=<UUID>&state=<64 base64url>`. The BFF consumes state once, rejects late logout callbacks and retrieves the terminal receipt privately. No receipt, token, asserted Person or authority travels in the callback URL. Session loss requires owning command readback, never restoring an old receipt.

`expected` has exactly eleven fields: `{personId,issuer,providerSubject,baseSessionId,clientId,contextId,appId,deploymentId,environment,action,payloadHash}`. `command` is `{operationKey,merchantBusinessId,organizationId}`. Deployment preserves the current Manifest snake_case ID and explicit environment; context is the registered opaque ZITADEL OPS organization ID, not a Business UUID.

## Native provider ceremony and action consume

The Login-origin component loads issued options without invoking WebAuthn until explicit user gesture. Platform verification is required. Server checks exact issued challenge, Login origin, RP hash, signed UP and UV, exact assertion hash and provider acceptance. A separate genuine Session API session is bound through provider metadata to the durable request. Both user/factor verification and fresh timestamp are inspected. A lost SetSession result reads the exact accepted assertion marker; it never resubmits an assertion. A lost creation result searches the exact reserved metadata, retires any confirmed orphan, and requires explicit restart when no actual accepted session can be established.

Public GET `/api/operations/actions/:requestId/challenge` uses `X-PayPM-Ceremony-Capability`. It returns `{requestId,action,publicKey,expiresAt,returnUrl}`. Public POST `/:requestId/complete` accepts `{capability,assertion}` and returns only the fixed callback URL. POST `/:requestId/cancel` accepts `{capability}`. Both require exact Login Origin. Cancellation is durable before redirect and rejects late verification; it can retire a verified, still-unused receipt. Same financial command can restart with a new request after cancellation without changing its operation UUID.

Private POST `/api/internal/v1/operations/actions/consume` uses distinct `PAYPM_OPERATIONS_ACTION_CONSUMER_TOKEN` and exact `{receipt,expected,command}`. Opaque receipt is exactly `/^paypm-ops1\.[A-Za-z0-9_-]{43}$/` (54 characters). It expires at the earlier of actual provider verifiedAt + 60 seconds and original five-minute request expiry, consumed once with SQL row lock. Uncertain consume outcome alone permits identical POST `/consumed/readback`; a mismatch/explicit rejection cannot be retried as new proof.

Success has exactly twenty fields: `{proofId,...expected,command,capabilityDecisionId,resource,proofSessionId,verifiedAt,expiresAt,consumedAt,assurance:'paypm_fresh_operations_passkey'}`. `resource` is `{merchantBusinessId,organizationId,currency}` from current owning authority. `proofSessionId` is the real fresh provider session and differs from base session. The independent consumer fixture is `apps/login/test-fixtures/operations-action-consume.json`.

Before public verification, private readback and consumption, Login rechecks raw token pair/current provider session/Identity eligibility, durable admission epoch and the current owning authority exact tuple/hash/resource/decision. Completion alone never implies financial success. Revoked admission denies immediately before provider retirement completes.

## Configuration and source gates

Migration `004_operations_action_requests.sql` adds encrypted caller proof/capability/provider material, immutable exact operation/request/assertion/evidence, row locks and forward state guards. `PAYPM_OPERATIONS_STORE_KEY_BASE64` is a separate canonical32-byte encryption key, never reused for workforce/flow/legacy/reader purposes. Database custody is the existing Login owner. `PAYPM_OPERATIONS_ACTION_CLIENT_POLICIES_JSON` is a strict unique nonempty `{clientId,callbackUrl}` array. Passkey origin/RP and registered current client policies must be exact. All readiness is still off until actual native client/provider qualification.

The fixed current owner reader is `/api/v1/internal/operations/authority/actions/current`, configured as `PAYPM_OPERATIONS_ACTION_AUTHORITY_URL`, with exact opaque `PAYPM_OPERATIONS_ACTION_AUTHORITY_KEY_ID` and separate `PAYPM_OPERATIONS_ACTION_AUTHORITY_API_KEY`. Sole scope is `operations.action.authority.read`; native HMACv2 binds exact raw JSON pathname/body/timestamp/nonce plus original paired raw headers. It rereads actual Operations grant/resource/state and canonical maker/checker truth. Login verifies the independent owner response and recomputes canonical command hash, never trusts an actor header.

A private POST `/api/internal/v1/operations/actions/cleanup` with the consumer-purpose credential and `{}` clears expired sealed credentials and queues real provider-session retirement. A configured job must run at least every60seconds; unavailable retirement remains durably pending and never restores admission. No cleanup service, secret, production database migration or provider grant has been deployed by this slice.

Source qualification includes actual SQL concurrency/idempotency/immutable/cancel/logout/expiry guards, independent real signature/hash/HMAC fixture, provider failure/lost-response boundary tests, bilingual component interaction tests, and actual source loopback browser composition at desktop/402px/320px. These synthetic browser checks have no provider or financial effects. Native staff passkey prompt, independently authorized actors, real provider callback/Origin, network isolation, producer→consumer command execution and deployed image remain separate release gates.
