# Identity Administration browser authentication bridge

Identity Administration retains the workforce ZITADEL issuer. The browser BFF owns server-only ID/access/refresh/nonce custody; this Login boundary proves the signed OIDC callback pair against the actual current Login-owned admission. Credentials, OTP verification and provider sessions remain Login/ZITADEL authority; Identity remains canonical people, invitation/eligibility and current staff capability authority. Admission supplies no recovery, directory or financial permission.

`POST /api/internal/v1/identity/admissions/check` takes exactly `{idToken,accessToken,nonce,clientId}` with separate `PAYPM_IDENTITY_ADMISSION_READER_TOKEN` (minimum32characters, distinct from all configured auth-purpose credentials). `PAYPM_IDENTITY_INTROSPECTION_CLIENT_ID/SECRET` are a separate exact provider resource client, not Operations credentials. `PAYPM_IDENTITY_OIDC_CLIENT_POLICIES_JSON` is a finite strict array of `{clientId,appId:'identity-administration',deploymentId,environment}`. Missing/duplicate/foreign policy denies. The registered workforce mode, verified invited email, active provider human and canonical workforce eligibility remain mandatory.

The exact22-field successful JSON is `{active:true,issuer,providerSubject,baseSessionId,clientId,tokenId,idTokenHash,accessTokenHash,nonceHash,personId,plane:'workforce',appId,deploymentId,environment,contextId,requestId,challengeId,authenticationClass:'workforce_limited',verifiedAt,absoluteExpiresAt,checkedAt,revocationVersion}`. The signed ID-token `sid` is the pinned ZITADEL Session API identifier, distinct from the access `jti`; signed original nonce and `at_hash` bind the pair. Current introspection requires active same-client/subject access with at most300-second lifespan. Native OTP factor timestamp, current8hour/30minute SQL admission and logout generation are independently reread; verified current use alone touches idle activity. No retirement-proof header or Operations policy fallback is returned. Any unavailable or invalid proof returns403 `{active:false}`, no-store.

`POST /api/internal/v1/identity/sessions/logout` takes that exact same4-field pair under distinct `PAYPM_IDENTITY_LOGOUT_TOKEN`. Apply migration006 before using the endpoint. Its hash-keyed immutable journal contains only the original admission/hash and affected provider session identifiers; tokens/nonce are not stored there. Local SQL admission/challenge/action retirement and the provider revocation queue commit atomically before any external provider effect. Other base sessions/global epoch remain unchanged. The exact14-field response is `{state:'revoked',personId,issuer,providerSubject,baseSessionId,clientId,contextId,appId,deploymentId,environment,revocationVersion,revokedAt,providerRetirement:'pending'|'confirmed',checkedAt}`. Confirmed is200; pending is503 with the same body and no-store. Identical accepted retries read the same journal and remaining queue even after admission expires; an unaccepted expired or changed pair denies403 `{error:'Identity logout unavailable'}`. This endpoint cannot restore authentication or grant permission. The BFF revokes its own browser session first and handles provider OAuth credential revocation through its registered client separately.
